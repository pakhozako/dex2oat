# Dex2oat Lock


![:name](https://count.getloli.com/@dex2oat?name=dex2oat&theme=moebooru&padding=7&offset=0&align=top&scale=1&pixelated=1&darkmode=auto)

## 🚀 项目简介

Dex2oat Lock 是一个面向 Android Root 模块环境的 ART / dexopt / dex2oat 属性调控模块。它通过规则包读取设备上的运行时属性、ROM 行为和 dexopt 相关配置，自动生成适合当前设备的 `system.prop`，并在启动和运行阶段持续维护关键状态。

模块的核心思路不是写入一组固定模板，而是根据设备实际环境进行规则匹配、配置生成、状态记录、健康检查与完整性校验。这样可以减少无效属性、重复属性和跨 ROM 迁移时的配置偏差。

## 🎯 设计目标 / 解决的问题

Android 的 ART / dexopt / dex2oat 行为会影响应用安装、后台维护、系统更新、空闲编译和运行时优化。不同 Android 版本、厂商 ROM、内核环境和 Root 实现对相关属性的支持并不完全一致，直接复制固定配置容易带来以下问题：

- 属性在当前 ROM 上无效，写入后没有实际作用。
- 多个模块同时写入同一属性，导致冲突或覆盖。
- 设备升级或 ROM 更换后，旧配置继续残留。
- 后台 dexopt 行为异常，带来额外发热、耗电或性能波动。
- 出现问题时缺少状态记录，难以判断是规则、属性还是运行环境导致。

Dex2oat Lock 通过规则驱动方式处理这些问题：安装时采集设备属性，按规则生成配置；运行时应用并校验关键属性；维护状态、快照、诊断和完整性报告，方便后续排查与恢复。

## 🔧 主要功能

### 规则驱动生成 `system.prop`

模块会解码内置规则包，读取设备已存在的 ART / dexopt / dex2oat 相关属性，并生成最终 `system.prop`。生成过程会记录命中规则数量、默认启用规则数量、忽略规则数量和最终生成属性数量。

当某条规则允许默认启用且设备没有采集到对应属性时，模块会使用规则定义的默认值生成配置，避免“规则存在但最终配置缺失”的情况。

### 统一属性写入流程

运行时属性写入使用统一流程：

```txt
resetprop -n
  -> 失败时
setprop fallback
```

模块会优先使用 `resetprop -n` 写入属性；如果不可用或写入失败，再回退到 `setprop`。属性写入结果会进入状态记录，便于后续查看和排查。

### Property Lock

模块会根据当前 `system.prop` 生成属性锁定列表，用于后续运行期校验和恢复关键属性。如果属性锁定列表生成失败，安装流程会以 WARN 展示，但不会直接阻断安装。

### 状态系统

模块使用 `/data/adb/dex2oat-lock` 作为运行状态目录，集中保存状态、日志、报告、快照和临时运行数据。核心状态会写入 `state.prop`，并通过 schema 校验、原子写入和锁机制降低并发写入或异常中断导致的状态损坏风险。

状态信息覆盖安装进度、规则匹配、配置生成、运行时应用、健康检查、完整性检查、冲突检测、快照、保护状态和诊断结果。

### 安装事务与失败恢复

安装流程包含事务准备、提交标记和失败回滚。安装开始前会清理旧版本状态目录和旧模块目录，避免旧文件干扰新版本。安装过程中如果发生失败，模块会尽量恢复上一版本状态；如果无法恢复，会保留事务目录供后续排查。

### 健康检查与完整性检查

健康检查用于确认模块生成的配置、运行状态和关键文件是否处于可用状态。完整性检查用于确认核心文件是否缺失或被修改。严重完整性问题会阻断安装，非关键异常会以 WARN 方式展示。

### 模块冲突检测

冲突检测会扫描其他已启用模块的 `system.prop`，查找是否存在与 Dex2oat Lock 管理属性相同的配置项。已禁用或待移除模块会被跳过，避免产生误报。

### 配置快照与回滚

在重新匹配规则或修改配置前，模块可保存最近配置快照。若新配置不符合预期，可以通过 Action 功能回滚最近一次快照。快照数量会进行轮转，避免长期积累占用过多空间。

### 诊断导出

模块支持生成诊断包，用于汇总状态、健康检查、完整性检查、冲突检测和规则匹配报告。诊断导出会对部分敏感信息进行脱敏处理，并限制导出文件大小。

### Action 操作入口

模块提供 `action.sh` 作为本地操作入口，可通过模块管理器的 Action 按钮或 shell 手动执行。常用能力包括：

```sh
sh action.sh status
sh action.sh rematch
sh action.sh apply
sh action.sh dry-run
sh action.sh diagnose
sh action.sh export
sh action.sh rollback
sh action.sh protection-reset
```

其中 `dry-run` 用于只读预演规则生成结果，不修改当前 `system.prop`、状态文件或运行时属性。

## 🧩 适用场景

Dex2oat Lock 适合希望减少不必要后台编译触发、降低安装和系统维护阶段资源占用，并希望保留可检查、可回滚配置流程的 Root 用户。

它尤其适用于以下场景：

- 希望统一管理 ART / dexopt / dex2oat 相关属性。
- 希望根据设备实际环境生成配置，而不是复制固定模板。
- 希望在刷机、升级、模块更新后快速重新生成当前设备适用配置。
- 希望检查其他模块是否写入了相同 ART / dexopt 属性。
- 希望保留安装日志、运行状态、健康检查和完整性检查结果，便于排查问题。
- 希望通过模块管理器标准 Action 入口完成常用维护操作。

## ⚠️ 注意事项

Dex2oat Lock 需要 Root 权限。模块会生成 `system.prop`，并在运行期尝试应用 ART / dexopt 相关系统属性。不同 ROM、Android 版本、内核和 Root 环境对这些属性的支持程度不同，生成配置不代表所有属性都会被系统实际采用。

修改 ART / dexopt 相关属性可能影响应用安装、后台优化、系统维护任务、功耗表现和性能表现。建议在安装前备份重要数据，并确保知道如何通过模块管理器禁用或卸载模块。

如果安装后发现异常，可以优先尝试：

1. 在模块管理器中禁用或卸载 Dex2oat Lock。
2. 通过 Action 查看当前状态和健康检查结果。
3. 重新匹配规则并生成 `system.prop`。
4. 回滚最近配置快照。
5. 导出诊断包后再进行进一步排查。

本模块只负责自身生成和维护的配置、状态与日志。设备 ROM、第三方模块或用户手动修改造成的系统级问题，仍需要结合实际环境单独分析。
