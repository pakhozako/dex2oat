# Dex2oat Lock v3.8 工作准备

> 历史归档：本文档记录 v3.7 之后进入 v3.8 的准备事项。当前后续路线以 `docs/V3.9_DEVOPS_AND_V4_ROADMAP.md` 为准。

本文档用于记录 v3.7 发布后进入 v3.8 的接续方向。当前 v3.7 发版状态不得因本文档改变版本号、模块行为、配置格式或发布包结构。

## 目标

- 继续保持 Magisk / KernelSU / APatch 模块结构兼容。
- 继续保持 BusyBox / POSIX Shell 兼容。
- 继续保持 Material Design 3 / Material You 设计语言。
- 优先处理真机反馈，不进行无目标的大规模重构。
- 所有功能改动继续遵循最小修改原则。

## 优先级

### P0 真机回归

- 基于真实 Magisk / KernelSU / APatch 刷入反馈，复核安装、升级、重启、卸载生命周期。
- 继续观察完整性状态、Manager 描述、WebUI 首页状态是否一致。
- 复核 `customize.sh`、`service.sh`、`uninstall.sh` 在真实 `/system/bin/sh`、Toybox、BusyBox 环境中的行为。
- 复核 `/data/adb/dex2oat-lock/` 状态目录权限、SELinux 约束和 WebUI 保存链路。

### P1 WebUI 体验

- 继续打磨启动页到主页的过渡动画，减少白屏、闪烁和布局跳动。
- 继续优化 Dialog、Snackbar、BottomSheet、按钮、卡片、导航、列表项和保存流程的 Motion 反馈。
- 复核所有页面是否仍存在重复文案、工程状态泄露或异常占位文本。
- 复核卡片透明度、模糊强度、自定义背景、深浅色和动态色在不同 WebView 中的表现。

### P1 配置与状态链路

- 继续加强跨档位配置 merge、备份、恢复和异常配置自愈。
- 保存生成 `system.prop` 时保持防重复提交、非阻塞反馈和明确错误原因。
- 复核诊断导出、配置摘要、安装历史弹窗与统一状态 `state.prop` 的一致性。

### P2 规则库

- 基于新增真机日志继续清理重复规则、命名和分类。
- 对可兼容升级为 `everything` 的 dexopt filter 继续做保守匹配，避免误写导致开机风险。
- 保持安全、谨慎、危险分类对用户足够清晰，但不在选项卡片上恢复噪声标签。

### P2 WebUI 保护

- 继续评估保护流程强度，优先保护规则库、Logo、歌词、封面和其它可拆包识别资源。
- 不为了保护强度牺牲旧 WebView 兼容性或页面启动速度。
- 构建后继续确认最终发布包不包含明文敏感资源。

## 禁止事项

- 不在 v3.7 发布提交中修改版本为 v3.8。
- 不改变 JSBridge API。
- 不改变现有配置 JSON 格式。
- 不新增未经评估的大型前端框架。
- 不恢复已删除的多入口彩蛋。
- 不把内部状态码、调试字段、`null`、`undefined`、`NaN` 暴露给用户。
